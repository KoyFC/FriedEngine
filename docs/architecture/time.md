# Time

`Time` holds the clock of the game, and it keeps two: the game's own and the real one. `Time.deltaSeconds` is the seconds the last frame lasted in the game's time, which is what every component's `update(delta)` and `Time.elapsedSeconds` follow, and `Time.unscaledDeltaSeconds` and `Time.unscaledElapsedSeconds` are the real seconds, for whatever must go on at the speed of the player and not of the game: a pause menu, a fade of the interface, a debug overlay.

`Time.timeScale` is how fast the game's time runs. 1 is real time, 0.5 is slow motion, 2 is twice as fast and 0 freezes every component's update, the fixed steps and so the physics, while the game keeps drawing and reading its input, which is how a pause menu is made: set it to 0, and let the menu read `unscaledDeltaSeconds`. The delta of a frame is first held to a quarter of a second, so a hitch does not become a jump, and then multiplied by the scale. `Time.fixedDeltaSeconds` does not change with the scale: a scaled game runs more or fewer fixed steps a second of real time, each of the same length, so physics behaves the same and only runs sooner or later. Because at most three steps run in a frame, a scale high enough to owe more than that makes the game run slower than the scale says, which is the same rule that keeps a slow frame from making the next one slower.

The clock is read in whole microseconds through `Clock` (`native/platform/clock.cpp`), and `Time` keeps each elapsed time as whole seconds and microseconds, turning it into the `Float` you read only when it is asked for. A `Float` counting seconds since 1970, which is what `Sys.time()` gives, cannot tell one frame from the next once a platform keeps a `Float` in 32 bits (see Platforms, the DS), and one that counts seconds since the game started loses its millisecond after a few hours, so the engine does not take its time from either. `Time.elapsedSeconds` is as exact as a `Float` allows when you read it and drifts by nothing however long the game runs; a game that needs a duration to the millisecond over hours should keep its own count of `Time.unscaledDeltaSeconds` in an `Int` of milliseconds, or take two `Clock.micros()` readings and `Clock.difference` between them.

Audio is not scaled: `Sound` and `Music` play on the native mixer in real time.

`Time.hostScale` is a second factor, on top of `timeScale`, that belongs to whoever runs the game and not to the game: the editor's speed control sets it, so a game that sets `timeScale` for its own slow motion does not undo what the person watching it chose.

`Application.isSuspended` is a debugger's pause and not a game's: while it is set the loop still reads events, draws and calls the update it was given, but no component updates and no fixed step runs, and the game's clock stands still while the real one goes on. `Application.stepFrame()` lets one frame through, in which the game's time moves by one fixed step and exactly one fixed step runs. The editor's Pause and Next Frame buttons use them.
