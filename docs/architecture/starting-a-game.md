# Starting a game

`fried.Bootstrap.run()` is a whole `main` for a game made the editor's way: it opens a window of the size `display` in `project.fried` names, creates the renderer, registers the game's nodes and every file in `assets/scenes` under its file name, and loads the scene named by `startScene` (the first one, by name, when there is none). A game has no class of its own to start: what a scene file cannot hold is a node's `ready()`, `update()` and `destroyed()`, and what the whole game needs, such as a second window, music or a saved score, is a node in an autoload scene. The nodes are the `@:serializable` classes in the game's `nodes` package, found by the macro `NodeDiscovery`, so there is no list to keep. The size, scene names and start scene are read from `project.fried` at compile time, like `Project.name()`.

The names `autoload` in `project.fried` lists are loaded after the nodes and scenes are registered and before the first scene, and then kept: loading another scene does not unload them, and their layers stay above the scene that is loaded. A name is either a node class, which is made once, as a Godot script autoload is, or a scene file, which is loaded like any other, so what the whole game needs is made of nodes. A class is looked for first, and it must be `@:serializable` in the game's `nodes` package, like any node the engine can build. `SceneManager.autoload(name)` gives the scene: for a class it holds one node with the class's name as its id, so `SceneManager.autoload("MusicPlayer").getById("MusicPlayer", MusicPlayer)` reaches it, and for a scene file any node of it can be reached by its id.
